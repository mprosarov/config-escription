# Дизайн-система и темы оформления

Документ описывает устройство стилей интерфейса, систему дизайн-токенов,
правила создания новых тем и план развития дизайн-системы.

Продуктовый стандарт оформления (правила современного дизайна) —
[design-rules.md](design-rules.md); все изменения UI должны им соответствовать.

---

## 1. Как устроены стили проекта

Интерфейс строится динамически из JSON-конфигурации (`example/src/elements/*.js`)
на основе **Bootstrap 5.0.2**, **bootstrap-icons** и **Tabulator** (тема semanticui).
CSS не препроцессорится: файлы конкатенируются утилитой `rigger` по списку
в `example/src/_app.css` в единый `dist/css/app.css`.

Порядок подключения (важен — позднее правило перекрывает раннее при равной специфичности):

```
css/bootstrap.min.css            — фреймворк
css/bootstrap-icons.min.css      — иконки
css/tabulator_semanticui.min.css — тема таблиц Tabulator
css/theme.css                    — ТОКЕНЫ ТЕМ + компонентный слой (перекрытие Bootstrap)
css/sidebars.css                 — каркас страницы, offcanvas
css/loader.css                   — индикатор загрузки
css/style.css                    — структурные стили компонентов приложения
css/modal.css                    — модальные окна (vnf-modal)
css/filter.css                   — окно фильтрации таблицы
css/log-panel.css                — панель логов действий
```

### Три слоя в `theme.css`

| Слой | Что содержит | Кто правит |
|------|--------------|-----------|
| **1. Токены темы по умолчанию** (`:root`) | Семантические переменные: цвета, типографика, отступы, радиусы, тени, анимации, размеры макета | Один раз при изменении брендбука |
| **2. Альтернативные темы** (`:root[data-theme="…"]`) | Переопределение тех же токенов под тему (пример: `dark`) | Автор новой темы |
| **3. Компонентный слой** | Перекрытие стилей Bootstrap 5.0.2 и базовых элементов; читает **только токены** | При добавлении нового компонента |

Почему компонентный слой нужен: Bootstrap 5.0.2 не поддерживает `data-bs-theme`
и компилирует цвета компонентов в hex-значения, поэтому кнопки, меню, формы,
вкладки и offcanvas перекрываются правилами, которые ссылаются на токены.
Благодаря этому **смена темы = смена значений токенов**, компоненты не трогаются.

## 2. Каталог токенов

Именование семантическое (по назначению, а не по цвету): `--accent`, а не `--blue-500`.
Примитивы палитры (`--blue-*`, `--slate-*`) объявлены в `:root` и используются
только для построения семантических токенов темы.

### Поверхности
| Токен | Назначение |
|-------|-----------|
| `--bg-page` | Фон страницы |
| `--bg-surface` | Карточки, navbar, offcanvas, модальные окна |
| `--bg-subtle` | Вторичные подложки: заголовки таблиц, `input-group-text`, шапка log-панели |
| `--bg-hover` | Hover-состояния строк и пунктов |
| `--bg-active` | Active/нажатые состояния |
| `--bg-inset` | «Утопленный» контейнер (сегментные вкладки) |
| `--bg-raised` | Активная «пилюля» над inset-контейнером |

### Границы
`--border-subtle` (разделители), `--border-default` (контролы, таблицы), `--border-strong` (акценты, скроллбары, чекбоксы).

### Текст
`--text-primary`, `--text-secondary`, `--text-muted`, `--text-inverse`, `--text-link`.

### Акцент и статусы
| Группа | Токены |
|--------|--------|
| Акцент (бренд) | `--accent`, `--accent-hover`, `--accent-active`, `--accent-subtle`, `--accent-contrast`, `--focus-ring` |
| Успех | `--success`, `--success-hover`, `--success-subtle` |
| Ошибка | `--danger`, `--danger-hover`, `--danger-subtle` |
| Предупреждение | `--warning`, `--warning-hover`, `--warning-subtle` |
| Информация | `--info`, `--info-hover`, `--info-subtle` |
| Вторичный | `--secondary`, `--secondary-hover`, `--secondary-subtle` |

Каждый статус имеет три формы: основной цвет (текст/иконка/граница), hover и
`*-subtle` (мягкая подложка). Контурные кнопки `btn-outline-*` собираются из них же.

### Типографика
`--font-sans` (Inter первым в стеке, fallback — системные шрифты; внешние
загрузки шрифтов не используются), `--font-mono`, размеры `--text-xs … --text-3xl`
(основной текст — `--text-base` / 15px, контролы и таблицы — `--text-sm` / 14px),
веса `--font-normal/medium/semibold`, межстрочные `--leading-tight/normal`.

### Отступы, радиусы, тени, анимации
- Отступы: шкала 4px — `--space-1 (4px) … --space-12 (48px)`. Использовать только её, произвольные `px`/`%` запрещены.
- Радиусы: `--radius-sm (6px)`, `--radius-md (8px)`, `--radius-lg (12px)`, `--radius-full`.
- Тени: `--shadow-sm` (карточки), `--shadow-md` (navbar), `--shadow-lg` (dropdown, offcanvas, модальные окна).
- Анимации: `--duration-fast (120ms)`, `--duration-base (200ms)`, `--ease`.

### Макет
`--navbar-height`, `--offcanvas-width`, `--offcanvas-top-height`.
Старые имена `--headerHeigth`, `--offcanvasTopHeigth`, `--offcanvasRightWidth/LeftWidth`
оставлены как legacy-алиасы и указывают на новые токены.

## 3. Правило создания новой темы

Тема — это блок переопределений семантических токенов под уникальным значением
атрибута `data-theme` на `<html>`. Компонентный слой и остальные CSS-файлы менять **не нужно**.

### Шаги

1. **Скопировать шаблон.** Взять блок `:root[data-theme="dark"]` из `theme.css`
   целиком — это гарантированно полный набор токенов, которые нужно переопределить.

2. **Переименовать селектор**: `:root[data-theme="corporate-red"]`.

3. **Задать значения всех групп токенов** (чек-лист, пропуск группы = «дыра» в теме):
   - поверхности: `--bg-page`, `--bg-surface`, `--bg-subtle`, `--bg-hover`, `--bg-active`, `--bg-inset`, `--bg-raised`;
   - границы: `--border-subtle`, `--border-default`, `--border-strong`;
   - текст: `--text-primary`, `--text-secondary`, `--text-muted`, `--text-inverse`, `--text-link`;
   - акцент: `--accent`, `--accent-hover`, `--accent-active`, `--accent-subtle`, `--accent-contrast`, `--focus-ring`;
   - пять статусных триад (`success/danger/warning/info/secondary`);
   - при необходимости: тени (`--shadow-*`).

4. **Соблюсти контраст**: текст `--text-primary` по `--bg-surface` — не ниже 4.5:1
   (WCAG AA), `--accent-contrast` по `--accent` — не ниже 4.5:1 для filled-кнопок.

5. **Учесть специальные случаи**: если в теме стрелка `select` или иконки плохо
   видны, добавить точечное правило по образцу
   `:root[data-theme="dark"] .form-select { background-image: … }`.

6. **Подключить тему**. Один из способов:
   - атрибут в `dist/template.html`: `<html lang="ru" data-theme="corporate-red">`;
   - URL-параметр: `index.html?config=main&theme=corporate-red` — встроенный
     скрипт в `<head>` применит его до загрузки CSS и запомнит в `localStorage['ui-theme']`;
   - программно: `document.documentElement.setAttribute('data-theme', 'corporate-red')`.

7. **Проверить** все состояния компонентов: navbar, меню (включая вложенные
   submenu), вкладки, кнопки всех шести вариантов (outline + disabled),
   формы (focus/disabled), таблицы Tabulator (чётные строки, hover, выделение),
   offcanvas со всех четырёх сторон, модальные окна, фильтр, log-панель, лоадер.

### Запреты

- Литеральные цвета (`#fff`, `rgb(...)`) в файлах компонентного слоя
  (`style.css`, `modal.css`, `filter.css`, `log-panel.css`, `loader.css`,
  `sidebars.css`) — **запрещены**. Допустимы только в слоях 1–2 `theme.css`.
- Запрещено переопределять в теме несемантические свойства (размеры, отступы,
  раскладку) — тема меняет только внешний вид, не геометрию.
- Новый компонент обязан читать токены; правило с hex-цветом не принимается в review.

## 4. Что улучшено в текущей ревизии дизайна

Текущая тема по умолчанию — светлая деловая: прохладный серо-голубой фон
страницы, мягкие белые поверхности, глубокий синий акцент, шкала отступов
4px, радиусы 6–12px, тонкие скроллбары, единое focus-кольцо `--focus-ring`
для доступности.

Ревизия 2 — продуктовая переработка по правилам [design-rules.md](design-rules.md):

- **Карточная система**: блоки верхнего уровня страницы (`.app-page > .itemsBlock`,
  `.tab-content`, `.table-tabulator-wrapper`) — карточки с тонкой границей,
  мягкой тенью и паддингом 20px; вложенные блоки остаются плоскими;
- **`orientation` из конфига заработал**: `.itemsBlock` стал flex-контейнером
  (раньше утилиты Bootstrap `flex-row`/`flex-column` не действовали без
  `display: flex`); `row`-блоки выстраивают колонки в строку и переносятся на
  узких экранах (`flex: 1 1 260px`);
- **Сегментные вкладки** («утопленный» контейнер `--bg-inset` + активная
  «пилюля» `--bg-raised`) вместо underline-вкладок;
- **Чистая сетка таблиц**: без зебры и вертикальных линий в теле, тонкие
  разделители строк, увеличенный паддинг ячеек, единый hover и выделение;
- **`btn-outline-secondary` — «тихая» кнопка** (нейтральная рамка, без цветного
  заполнения): визуальная иерархия действий;
- **Типографика**: основной текст 15px, контролы и таблицы 14px, Inter первым
  в стеке шрифтов, сдержанная шкала заголовков с отрицательным letter-spacing;
- **Плоский navbar** (тень убрана, оставлена граница снизу) и глобальный
  `:focus-visible` для клавиатурной навигации (WCAG 2.4.7).

Попутно устранено:
- глобальное правило `h5 { color: steelblue; text-align: center }` — не влияло
  на компонент Header (он создаёт `div.h5`, а не `<h5>`), но ломало бы любой
  реальный `<h5>`; заменено на стилизацию заголовка в `.navbar-brand`;
- мёртвые стили `.btn-toggle*`, `button[data-type="sidebar"]` из примера
  документации Bootstrap в `sidebars.css` (в том числе `background-color: black`
  и красный hover) — компоненты их не используют;
- невалидные свойства `_background` / `_border-left` в тулбаре таблицы;
- устаревший атрибут `data-mdb-theme="dark"` в `template.html` (MDB в проекте не используется);
- дубли правил `.navbar` (padding задавался в трёх местах);
- разнобой единиц (`2%`, `12px`, `1rem`) переведён на шкалу `--space-*`.

## 5. Что можно улучшить дальше (аудит)

1. **Инлайн-стили в JS-компонентах.** `cNavBar.js` (flex-контейнер меню),
   `cButton.js` (`width: fit-content`), `cSideBar.js` (`font-size: 0; z-index`)
   встраивают стили в HTML-строки. Вынести в классы (`navbar-menu-stack`,
   `btn-sidebar-toggle`) — иначе их нельзя thème-овать и переопределять.
2. **`manager.html`** использует инлайновые цвета (`background-color: #f8f8f8`,
   `#eaebeb`) — перевести на токены, добавить поддержку `data-theme`.
3. **Опечатка `--headerHeigth`** (Height) живёт в legacy-алиасах; после перехода
   всех правил на `--navbar-height` алиасы удалить.
4. **Tabulator** подключён с темой `semanticui`, которая спорит с нашей
   палитрой; сейчас перекрыты только основные элементы. Полноценное решение —
   собрать кастомную тему Tabulator из тех же токенов или перенести все
   перекрытия в один файл `tabulator-theme.css`.
5. **Статусы элементов в конфигах** несогласованы: `unabled` (вместо `enabled`),
   `desabled`, пустые строки и булевы значения в одном поле `status`. Унификация
   упростит и стилизацию disabled-состояний.
6. **`btn-toggle` и прочий мёртвый CSS** удалены в этой ревизии — список в разделе 4.
7. **Доступность**: проверить контраст всех пар токенов инструментом (axe/Lighthouse),
   добавить `:focus-visible`-стили для навигации клавиатурой по dropdown.
8. **Шрифт**: системный стек стабилен, но для единого вида на всех ОС можно
   подключить self-hosted Inter/PT Root Sans (офлайн-контур это позволяет).

## 6. Дальнейшие шаги по организации дизайн-системы

1. **Обновить Bootstrap до 5.3.x** — появятся нативный `data-bs-theme` и
   компонентные переменные (`--bs-btn-*`, `--bs-dropdown-*`): большая часть
   слоя 3 станет не нужна, тёмная тема заработает «из коробки».
2. **UI-переключатель темы**: кнопка/селект в navbar + сохранение выбора через
   существующий механизм `saveuserinterfaceconfig` (тема как часть пользовательского конфига).
3. **Живой styleguide**: демо-конфигурация `styleguide.json` со всеми типами
   элементов — визуальная регрессия тем без ручного обхода страниц.
4. **Линтер цветов**: stylelint с правилами `color-no-hex` +
   `declaration-property-value-disallowed-list` для файлов вне `theme.css` —
   запрет литеральных цветов на уровне CI (можно встроить в `.github/workflows`).
5. **Документирование токенов**: автогенерация таблицы токенов из `theme.css`
   (или Storybook, если появится сборка компонентов).
6. **Токены как источник правды**: вынести палитру в JSON (design tokens format)
   и генерировать `theme.css` — единый источник для веб и будущих серверных отчетов.
